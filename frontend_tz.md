# Техническое задание: Разработка пользовательского интерфейса и слоя представления (Frontend/UI)

## 1. Общие сведения и назначение модуля

### 1.1. Назначение

Модуль графического интерфейса пользователя (**Frontend/UI**) представляет собой десктопное приложение на базе фреймворка **Qt (C++17/C++20, QtWidgets)**, предназначенное для интерактивного управления параметрами моделирования дорожного движения, визуализации динамики транспортных и пешеходных потоков на перекрестке в реальном времени, а также отображения аналитических метрик заторов.

### 1.2. Архитектурный паттерн (Model-View-Presenter)

Взаимодействие интерфейса с вычислительным ядром строится по шаблону **MVP (Model-View-Presenter)** с пассивным представлением (Passive View):

1. **Model (`ISimulationEngine`):** Вычислительное ядро симуляции. Полностью изолировано от UI-библиотек.
2. **Presenter (`SimulationPresenter`):** Посредник, управляющий циклом рендеринга (таймер $\Delta t$), передающий конфигурации в модель и транслирующий срез состояния (`SimulationSnapshot`) графической сцене.
3. **View (`MainWindow`, `SimulationView`, `SimulationScene`, панели управления):** Слой отображения. Принимает пользовательский ввод со слайдеров/тумблеров и отображает объекты мира исключительно на основе данных из `SimulationSnapshot`.
4. **Автономность разработки через заглушку:** До завершения разработки боевого бэкенда фронтенд функционирует с `MockSimulationEngine`, реализующим генерацию тестовой геометрии, фиктивное движение объектов и смену фаз светофоров.

## 3. Спецификация слоя отображения (Canvas / Graphics)

### 3.1. Представление и сцена (`SimulationView`, `SimulationScene`)

1. **Настройки `SimulationView`:**
   * Включение сглаживания: `QPainter::Antialiasing`, `QPainter::TextAntialiasing`, `QPainter::SmoothPixmapTransform`.
   * Режим обновления: `QGraphicsView::SmartViewportUpdate` или `FullViewportUpdate`.
   * Масштабирование: преобразование физических единиц (метры) в экранные пиксели (рекомендуемый базовый масштаб $S = 10\dots 15\text{ px/м}$).
   * Поддержка изменения масштаба колесом мыши (`wheelEvent`) в диапазоне $0.5\times \dots 3.0\times$ и панорамирования сцены зажатием средней кнопки мыши / пробела.

2. **Отрисовка дорожной инфраструктуры (`RoadGraphicsItem`):**
   * Параметрическая отрисовка подходов в зависимости от `IntersectionTopology`:
     * **2+2:** по 2 полосы на каждом подходе (ширина полосы $w = 3.5\text{ м}$).
     * **3+3:** по 3 полосы на каждом подходе.
     * **2+3 (Асимметрия):** подходы Север-Юг — 2 полосы, Восток-Запад — 3 полосы.
   * Нанесение разметки:
     * Осевая двойная сплошная линия (разделитель встречных потоков).
     * Прерывистые линии между попутными полосами.
     * Стоп-линии перед каждым подходом на расстоянии $d_{stop}$ от геометрического центра перекрестка.
     * Разметка пешеходных переходов («зебра») шириной $3.0\text{ м}$ на всех активных направлениях.

### 3.2. Графический элемент автомобиля (`VehicleGraphicsItem`)

1. **Геометрия и габариты:**
   * Прямоугольник со скругленными углами согласно полям `VehicleRenderData::length` ($\approx 4.5\text{ м}$) и `width` ($\approx 1.8\text{ м}$).
   * Центр вращения совпадает с геометрическим центром автомобиля; ориентация задается вектором скорости `velocity`:
     
     $$\theta = \operatorname{atan2}(v_y, v_x)$$

2. **Цветовая дифференциация направлений (требование ТЗ):**
   Цвет заливки корпуса автомобиля однозначно кодирует его намерение (`TurnIntent`):
   * **Движение прямо (`Straight`):** Синий / Сине-голубой (`#2196F3`).
   * **Поворот налево (`Left`):** Янтарный / Оранжевый (`#FF9800`).
   * **Поворот направо (`Right`):** Фиолетовый / Пурпурный (`#9C27B0`).

3. **Световая индикация состояния:**
   * **Стоп-сигналы:** При значении `isBraking == true` задние габаритные огни подсвечиваются ярко-красным цветом (`#FF0000`).
   * **Индикаторы поворота:** При маневрах налево/направо соответствующий угловой маркер пульсирует желтым светом с частотой $1.5\text{ Гц}$.
   * **Очередь:** Опциональная подсветка контура при `isWaitingInQueue == true`.

### 3.3. Графический элемент пешехода (`PedestrianGraphicsItem`)

* Пешеход отрисовывается в виде кругового маркера диаметром $0.8\text{ м}$ ($\approx 8\dots 12\text{ px}$).
* Цвет заливки:
  * В ожидании на островке/тротуаре: Нейтральный серый / Белый (`#ECEFF1`).
  * В процессе перехода проезжей части (`isCrossing == true`): Ярко-зеленый или Желтый (`#00E676`).
* Отображение счетчика ожидающих пешеходов на островках (`CrosswalkRenderData::waitingPedestriansCount`) в виде компактного бейджа с числом.

### 3.4. Графический элемент светофора (`TrafficLightGraphicsItem`)

* Размещение перед каждой стоп-линией на обочине и консоли над полосами.
* Отрисовка трех классических линз: Красный (верх), Желтый (центр), Зеленый (низ).
* **Дополнительные секции со стрелками (согласно эскизу на доске):**
  * **Левая стрелка:** Секция слева от зеленого сигнала. Отрисовывается контур стрелки налево:
    * `ArrowState::None` — секция отсутствует.
    * `ArrowState::Off` — секция выключена (темный кружок с контуром стрелки).
    * `ArrowState::Green` — активная зеленая стрелка.
  * **Правая стрелка:** Секция справа от зеленого сигнала (контур стрелки направо, логика аналогична).
* **Пешеходные светофоры:** Двухсекционный мини-светофор («Красный стоящий человечек» / «Зеленый идущий человечек») у каждого конца зебры.

## 4. Панели управления и интерактивная логика (`panels/`)

### 4.1. Панель параметров (`ParametersPanel`) — перенос схемы с доски

Панель должна повторять элементы управления, зафиксированные на проектных эскизах доски:

```
┌────────────────────────────────────────────────────────┐
```

#### 4.1.1. Математическая взаимная блокировка слайдеров (Формула с доски)

При перемещении одного из ползунков фаз в статическом режиме, второй ползунок должен двигаться автоматически в противоположную сторону согласно математическому инварианту:

$$T_K = \frac{T_{общ}}{N_{фаз}} - T_Z$$

**Требования к UI-логике:**
1. При изменении слайдера $T_Z$ (Зеленый сигнал):
   * Вычисляется новое значение $T_K = \operatorname{clamp}\left(\frac{T}{N} - T_Z, T_{K\_min}, T_{K\_max}\right)$.
   * Вызывается блокировка сигналов слайдера $K$ (`sliderK->blockSignals(true)`), устанавливается значение и снимается блокировка (`blockSignals(false)`).
2. При изменении общего цикла $T$:
   * Пропорционально пересчитываются $T_Z$ и $T_K$.
3. Количество активных фаз $N_{фаз}$ определяется положением тумблеров:
   * Базовый 2-фазный цикл: $N_{фаз} = 2$.
   * Включены защищенные левые стрелки (`permitLeftTurnFilter == false`): $+2$ фазы.
   * Включена эксклюзивная пешеходная фаза (`hasPedestrianPhase == true`): $+1$ фаза.

#### 4.1.2. Реактивное поведение элементов управления

1. **Переключение режима `Auto / Man` (Static / Dynamic):**
   * При выборе `Auto (Адаптивный)` блок ручных слайдеров фаз ($T$, $З$, $К$) **скрывается или становится неактивным (`setEnabled(false)`)**, так как контроллер сам управляет длительностями (пометка на доске: *«пропадёт при выборе auto (не имеет смысла)»*).
2. **Зависимость пешеходного слайдера $З_п$:**
   * Ползунок длительности пешеходного зеленого $З_п$ активен **только при отключенной дополнительной стрелке** или при включенной эксклюзивной пешеходной фазе (пометка на доске: *«$З_п$ активен только при стрелка OFF»*).
3. **Отправка конфигурации:**
   * При изменении любого слайдера или тумблера панель генерирует сигнал `configChanged(const SimulationConfig& config)`.
   * Для предотвращения перегрузки бэкенда при быстром перетаскивании ползунка применяется таймер задержки (debounce $50\text{ мс}$) перед окончательной отправкой в презентер.

### 4.2. Панель управления симуляцией (`ControlPanel`)

Содержит управляющие кнопки жизненного цикла процесса моделирования:
* **Старт / Пауза (Play/Pause):** Запуск и приостановка внутреннего таймера презентера.
* **Сброс (Reset):** Очистка сцены, возврат времени симуляции к $0.0\text{ с}$, очистка статистики.
* **Одиночный шаг (Step):** Выполнение одного дискретного шага симуляции ($\Delta t$) для покадрового анализа сложного маневра.
* **Масштаб времени (Time Scale):** Дискретные кнопки или выпадающий список: $0.5\times$, $1.0\times$ (реальное время), $2.0\times$, $5.0\times$, $10.0\times$.

---

### 4.3. Панель аналитики и метрик (`StatsPanel`)

Отображение показателей эффективности в реальном времени из структуры `SimulationStatistics`:

1. **Числовые индикаторы (KPI Cards):**
   * **Средняя задержка ($\overline{W}$):** среднее время ожидания остановленных автомобилей перед перекрестком (в секундах).
   * **Максимальная задержка ($W_{max}$):** максимальное время нахождения в очереди одного автомобиля.
   * **Количество обслуженных авто ($M$):** счетчик машин, успешно пересекших перекресток.
   * **Текущая очередь ($Q$):** суммарное число автомобилей с $v < 0.5\text{ м/с}$ на всех подходах.
   * **Фактическая пропускная способность:** авто/час.
2. **Динамический мини-график:**
   * Построение кривой изменения суммарной очереди $Q(t)$ за последние $60$ секунд симуляции (с использованием `QChart` / `QLineSeries` или кастомного `paintEvent`).

### 5.2. Реализация заглушки ядра (`MockSimulationEngine.h/.cpp`)

Для изолированной работы фронтенд-разработчика создается автономный класс `MockSimulationEngine`, реализующий `ISimulationEngine`:

1. **Генерация трафика:** Каждые $2.0\text{ с}$ создает виртуальный автомобиль на случайном подходе.
2. **Траектории:** Автомобили плавно перемещаются по прямой со скоростью $v = 10\text{ м/с}$ к стоп-линии.
3. **Светофор:** Циклически переключает `LightColor::Green` ($5\text{ с}$) $\to$ `LightColor::Yellow` ($2\text{ с}$) $\to$ `LightColor::Red` ($5\text{ с}$).
4. **Реакция на стоп-линию:** Если свет красный — скорость снижается до $0$, устанавливается флаг `isWaitingInQueue = true` и `isBraking = true`. Если свет зеленый — автомобиль проезжает перекресток и удаляется.
5. **Пешеходы:** Фиктивная группа из $2$ точек переходит дорогу при красном сигнале для авто.

## 6. Требования к UI/UX и стилизации (`style.qss`, `resources.qrc`)

1. **Цветовая палитра темы (Dark Modern / Engineering UI):**
   * Фон главного окна: `#1E1E24` (темно-серый угольный).
   * Фон холста симуляции (асфальт): `#2B2D42`.
   * Цвет разметки: `#FFFFFF` (белый) и `#F4D03F` (желтый для осевых).
   * Цвет панелей управления: `#252836` с границами `#3A3F55`.
   * Акцентный цвет интерактивных элементов: `#3D5AFE` (индиго-синий).
2. **Слайдеры (`QSlider`):**
   * Каждый слайдер обязан сопровождаться поясняющим `QLabel` с текущим числовым значением и единицами измерения (например: `600 авт/ч`, `30 с`, `60 м`).

3. **Респонсивность и компоновка:**
   * Центральная область (`SimulationView`) занимает приоритетное пространство ($70-75\%$ ширины окна).

2. **Подмена инициализации объекта:**
   ```cpp

   // auto engine = std::make_shared<MockSimulationEngine>();

   // СТАЛО (Финальная сборка с боевым ядром):

   m_presenter = std::make_unique<SimulationPresenter>(engine, this);
   ```

## 8. Критерии приемки фронтенда

1. **Автономность запуска:** Проект собирается через `CMake` и запускается без ошибок в окружении только с заглушкой `MockSimulationEngine`.
2. **Корректность FSM-слайдеров:** При изменении слайдера $З$ слайдер $К$ мгновенно и корректно пересчитывается в соответствии с формулой взаимной блокировки, исключая «залипание» и взаимное рекурсивное зацикливание сигналов.
3. **Стабильность частоты кадров:** Сцена плавно обновляется при отображении до $150$ одновременных автомобилей и $50$ пешеходов с частотой не менее $30\text{ FPS}$.
4. **Визуальная различимость:** Цвет автомобиля однозначно позволяет определить его запланированный маневр (прямо/налево/направо).
5. **Корректность переключения режимов:** Переключение между топологиями $2+2$, $2+3$, $3+3$ динамически перестраивает разметку и полосы на холсте без перезапуска приложения.
