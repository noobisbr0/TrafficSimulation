## Возможности системы

* **Физика движения и следование за лидером**:
  * Реализация модели водителя **IDM (Intelligent Driver Model)** с учетом безопасной дистанции и разности скоростей.
  * Разрешение «дилеммы желтого сигнала» светофора (остановка с комфортным замедлением или завершение проезда при превышении порога экстренного торможения).
  * Расчет траекторий поворота ТС по дугам окружностей с динамическим снижением скорости.
* **Гибкая топология перекрестка**:
  * $2+2$: перекресток двух четырехполосных дорог.
  * $2+3$: асимметричный перекресток (2 полосы «Север–Юг», 3 полосы «Восток–Запад»).
  * $3+3$: перекресток двух шестиполосных дорог.
* **Режимы светофорного регулирования**:
  * **Статический режим**: фиксированные интервалы зеленого ($Z$), красного ($K$), желтого сигналов и пешеходных фаз.
  * **Адаптивный (динамический) режим**: автоматическое продление зеленой фазы (шагами по 2 с) при наличии очереди в зоне видимости детектора $D$ с защитой от блокировки поперечных направлений.
* **Дополнительные настройки маневрирования**:
  * Режим «просачивания» (ВСТР): поворот налево через встречный поток с уступкой дороги либо выделенная левая стрелка.
  * Пешеходное регулирование: пропуск пешеходов параллельно попутному автотранспорту либо выделенная общепешеходная фаза («All-Red»).
* **Стохастическая генерация потоков**:
  * Моделирование пуассоновских потоков автомобилей и пешеходов на основе экспоненциального распределения интервалов прибытия.
* **Интерактивный UI и аналитика**:
  * 2D-визуализация на базе `QGraphicsView` с поддержкой зума и панорамирования.
  * Детализированная графика автомобилей (габариты, стоп-сигналы, поворотники, цветовая дифференциация маневров).
  * График изменения очереди в реальном времени за последние 60 секунд.
  * Экспорт накопленного временного ряда показателей симуляции в **CSV**.

## Архитектура проекта

Проект спроектирован по архитектурному шаблону **Model-View-Presenter (MVP)**:
* **Core (Model)**: статическая библиотека `TrafficCore`, содержащая физику движения, сущности, контроллеры и сбор статистики. Не зависит от виджетов интерфейса.
* **UI (View)**: графический интерфейс на Qt6 Widgets (`QGraphicsScene`, док-панели управления и статистики).
* **Presenter**: класс `SimulationPresenter`, обеспечивающий связь модели и интерфейса через снимок состояния `SimulationSnapshot` и фасад `ISimulationEngine`.

## Сборка и запуск

### Требования
* Компилятор C++ с поддержкой стандарта **C++17** (GCC $\ge 9$, Clang $\ge 10$)
* **CMake** $\ge 3.16$
* **Ninja** или Make
* **Qt 6** (компоненты: `Core`, `Gui`, `Widgets`)

### Сборка через CMake
```bash
git clone https://github.com/noobisbr0/TrafficSimulation.git
cd TrafficSimulation

cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build

./build/TrafficSimulation
```

### Запуск через Nix-shell
Если у вас установлен пакетный менеджер Nix, всё окружение (компилятор, Qt6, CMake, Ninja) разворачивается автоматически:
```bash
nix-shell
cmake -B build -G Ninja
cmake --build build
./build/TrafficSimulation
```

## Управление симуляцией

* **Старт / Пауза**: запуск и остановка цикла моделирования.
* **Шаг**: дискретное продвижение времени симуляции на один расчетный квант времени $\Delta t$.
* **Сброс**: очистка сцены перекрестка, сброс таймеров и счетчиков статистики.
* **Скорость**: регулировка множителя скорости воспроизведения от $0.1\times$ до $5.0\times$.
* **Масштабирование**: колесо мыши над областью перекрестка.
* **Панорамирование**: зажатие левой кнопки мыши и перемещение курсора.
* **Экспорт**: кнопка «Экспорт в CSV» на панели статистики сохраняет файл в директорию документов.
